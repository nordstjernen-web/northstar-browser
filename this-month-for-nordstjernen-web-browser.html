This month for the Nordstjernen web browser

A review of the last 30 days — 11 June to 11 July 2026. Ten point releases, the last absent rows in the HTML standard closed, and a hard push on real-world video, content blocking, on-device safety and platform reach — all while staying no-JIT and telemetry-free.

Nordstjernen (“the North Star”) is a web browser written from scratch in C, built in Norway — a clean-room engine small enough for one person to read end to end. This is what changed in the last month. If you only read one line: the engine grew from roughly 109,000 to about 145,000 lines of C, shipped ten releases (1.0.8 → 1.0.18), and reached zero absent rows in the in-scope HTML standard — every §1–§16 element and API is now implemented, partial, or a deliberate non-goal.

The month by the numbers

~109k → ~145k lines of C — the clean-room engine grew by about a third and is still small enough to audit end to end. No JIT; W^X holds process-wide.
140 / 31 / 0 — the section-by-section walk-through of the HTML standard (§1–§16) now records 140 rows fully implemented, 31 partial, and 0 absent, up from 123 / 48 / 4 at the start of the month.
+1 platform, −1 platform — a new iOS port that builds end to end in CI arrived; OpenBSD was retired. Android is now published on the Google Play Store.

Closing the last gaps in the HTML standard

Nordstjernen measures itself against the spec text, section by section, rather than against another browser. This month the running scoreboard crossed a symbolic line: no element or API row in §1–§16 is fully absent any more. Everything is implemented, tracked as partial, or a by-design non-goal (plugins, frame/frameset, applet/marquee, telemetry, and AI-style web APIs). The remaining work is now refinement of partial rows — multi-column vertical text, iframe srcdoc, quirks-mode deltas — not blank spaces.

JavaScript conformance got the same treatment: several deep passes against the test262 suite drove the unexpected-failure count down (one pass went from 28 to 15), alongside a stream of spec-accuracy fixes to DOM nodes, CSSOM serialization, forms, fetch, encodings, history and messaging. A serve-free local web-platform-tests runner (wpt-local.sh) was added so conformance can be checked without standing up a server.

Real-world video, done the small way

The largest single theme of the month was making inline video work on real sites — without importing a media stack. The pieces came together across several releases:

  • WebM playback (1.0.14). <video> now decodes VP9/VP8 with Opus/Vorbis inline when FFmpeg’s libav* is present — the system copy on Linux, a minimal LGPL build bundled on macOS and Windows. MPEG-1 still always plays, decoded in-tree by pl_mpeg.
  • Media Source Extensions. Streaming sites that drive playback through MediaSource/SourceBuffer and blob: now play inline. A dedicated, sandboxed nordstjernen-video helper process decodes the stream and the shell composites its frames over the page — and it was ported to both Windows and macOS this month, with audio-clock (audio-master) A/V sync and incremental demuxing of growing streams.
  • Captions. A default <track> of WebVTT subtitles is fetched, parsed into timed cues, and painted over the bottom of the video.
  • No more site hacks. YouTube-specific media scraping and assorted per-site paint/layout hacks were removed in favour of a standards-based media-metadata extractor. The house rule is explicit: improve the generic engine to run real sites, rather than special-casing them.
  • Native open-media decoders. So WebM and Ogg still play where FFmpeg is absent, Nordstjernen now detects and links dav1d, libvpx, Opus, Vorbis (and libvorbisfile / native Ogg Opus), and vendored the small libnestegg WebM demuxer.

Underneath all of this, the audio path was rebuilt (1.0.10): SDL2 output with in-tree pl_mpeg (MP2) and minimp3 (MP3) decoding replaced the previous vendored backend, keeping audio as a handful of single-file decoders in a separate unsandboxed helper rather than a codec library in the renderer. Capture arrived too — camera and microphone via getUserMedia, each behind a per-site permission prompt.

Content blocking and on-device safety

Release 1.0.16 added two privacy-and-safety features that run entirely on your machine:

  • Initial WebExtensions support with content blocking. A WebExtensions loader and content-script host (src/ext.c) implements declarativeNetRequest, so EasyList/ABP-style filter lists can block ads and trackers before requests go out.
  • Local Safe Browsing. Before a top-level navigation is fetched, its host is checked against an on-device SHA-256 blocklist (src/safebrowsing.c). A match shows a full-page warning with the choice to go back or continue. The check is entirely local — nothing about your browsing leaves the machine — and the list is user-overridable.

Networking, modernised

  • HTTP/2 multiplexing (1.0.12) over a shared libcurl multi handle — connections are reused across a page’s requests instead of reopened.
  • HTTP/3 is requested when the linked libcurl supports it, and WebSocket now rides libcurl’s native API exclusively (the hand-rolled RFC 6455 framer was dropped).
  • Encrypted Client Hello is enabled when the TLS backend offers it, and the post-quantum X25519MLKEM768 key exchange is used where available.
  • ES modules for real apps — <script type="importmap"> support (1.0.11) means bare specifiers like import "three" resolve, so modern bundler-free sites and three.js examples load; module workers (new Worker(url, {type:'module'})) landed as well.

More of the web platform

Beyond media, a batch of platform APIs and CSS features arrived:

  • Navigation API — window.navigation for single-page routing: a cancelable navigate event with intercept() and a full history-entry model.
  • Customized built-in elements — customElements.define(name, ctor, {extends}) plus <button is="…"> upgrade the built-in through the full reaction lifecycle.
  • WebCrypto gained Ed25519 and X25519, plus AES-KW key wrapping, over OpenSSL.
  • CSS & layout — vertical writing-mode for block containers with text-orientation/upright text, proper CSS-table cells with height distribution, :has() and container queries kept on the incremental-restyle path, calc() font sizes, real blurred box-shadow, interactive <select>/<datalist> listboxes, and createConicGradient on canvas.

A browser-wide security hardening pass

In keeping with the “small enough to audit” ethos, an end-to-end source review in early July produced dozens of hardening fixes at once. Among them:

  • Resource-exhaustion guards — caps on CSS custom-property var() expansion (billion-laughs), image dimensions (decompression bombs), IndexedDB connections in private mode, and oversized cache files.
  • Memory-safety fixes — use-after-free repairs across canvas, paint, WASM, WebGPU and the observer paths; a robust-buffer-access GL context to contain out-of-bounds vertex fetches; NaN-geometry guards in paint.
  • Sandbox & privilege — the video helper is now seccomp-confined, the macOS renderer and shell run under a Seatbelt sandbox, and on Windows the browser drops Administrator rights by relaunching de-elevated.
  • Network hygiene — stopped AUTOREFERER from leaking full URLs across cross-origin redirects, refused UTF-7 and replacement-mapped charsets in the decode path, and hardened the extension content-script bridge against cross-extension theft.

Platform reach

  • iOS — a new UIKit host app plus engine cross-compilation (is_mobile) and a CI portability workflow; the iOS build now compiles end to end in CI.
  • macOS — the published .dmg is now signed and notarised, ships Apple Silicon only, builds on the macOS 26 (Tahoe) runner, and gained WebGL 1 through a CGL core context.
  • Android — now on the Google Play Store, free and telemetry-free, with minSdk lowered to run on Android 14.
  • OpenBSD — retired (1.0.9): its base LibreSSL lacks the OpenSSL 3 provider APIs WebCrypto needs, so rather than ship a perpetually red nightly the target was dropped. FreeBSD and NetBSD remain.

Shell and UI polish

  • A Task Manager window — per-process CPU %, memory and thread counts, JVM-style thread dumps (on SIGQUIT), a watchdog row, and End Task that also cleans up media helpers.
  • Developer Tools — a tabbed console window, reachable with Ctrl+Shift+J / F12.
  • A non-modal permission bar replaced the old modal WebGL/camera trust dialogs; WebGL is now enabled by default. An HTTPS security shield sits left of the address bar, and private tabs stay out of session recovery.
  • A dedicated AI Window moved the local, on-device about:start assistant out of a browser tab, and the about:start splash was redesigned as an animated civilization-panorama scene.

Scope discipline: the email experiment

Not everything that was tried stuck — and that is by design. Around 1.0.17 an experimental built-in email client (about:email, IMAP/POP3/SMTP with provider auto-configuration, primary-password-encrypted credentials and attachment viewing) was added, and then removed a few days later to keep the browser focused on being a browser. The project’s guiding principle is to cut scope rather than corners; the email client is a clean example of that in action.

What stayed the same

Through all of it, the constraints held. Nordstjernen still ships no JIT (the renderer never needs writable-executable memory), no telemetry, and no auto-update pinger. Each tab’s engine still runs in its own sandboxed process behind an IPC and shared-memory boundary, seccomp- and Landlock-confined on Linux. The whole engine is still clean-room C, still vendored in-tree with no submodules, and still small enough for one person to hold in their head. A busy month — measured against a fixed North Star.
